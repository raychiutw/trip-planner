# ADR-0012：AI 資料同意由送出者與行程 owner 雙方持有，server 端把關

- **Status**：Accepted（模型；2026-11-03 `/grill-with-docs`）。文案中仍待 owner 提供的欄位見「未決」。
- **來源**：#1348（版本化 AI 資料同意）、Flutter #382／#390。

## Context

行程 AI（request、健檢、AI 筆記）會把資料交給外部處理方。現有的 `ai-authorization` 是 **AI 操作授權**（owner 讓 AI 以自己的身分改自己行程），只有一個布林，沒有版本，也不是資料同意。同時一筆 request 可能由旅伴（協作者）送出，但行程內容屬於 owner：AI 看得到送出者的訊息與顯示名稱，以及 owner 的行程內容。

## Decision

- **兩個概念分開命名、各自獨立**：AI 操作授權與 AI 資料同意，互不取代（見 GLOSSARY）。
- **雙方同意**：送出者與行程 owner 都要有有效的資料同意（owner 自己送時是同一人）。旅伴送出但 owner 尚未同意時，回覆「行程擁有者尚未同意」，不排入佇列。
- **由 server 判定，不由 client**：三個受管制入口（建立 request、行程健檢、AI 筆記）一律在 server 檢查；讀取類不管制。client 只讀狀態、顯示說明、提交決定。
- **同意綁定版本**，帳號層級、跨裝置一致；狀態為 none／stale／withdrawn／valid。實質變更才升版。
- **不回填**：舊的操作授權不視為已同意新版；上線後每位使用者下次用 AI 時一次性重新同意，同意前 AI 功能被擋、其餘功能照常。
- **資料最小化**：交給 AI 的請求資料只留送出者的顯示名稱，不含 email（需先改 api）。
- **撤回語意沿用 [ADR-0007](0007-request-termination-cancel-and-reap.md)**：撤回後新請求立即拒絕、排隊中尚未開始的被終結；**已開始的工作不保證能停**，已送出的資料收不回來，文案照實寫。
- 文案不承諾保存期間與訓練政策的具體數字，寫「依處理方條款，詳見連結」；處理方的實際設定經 owner 核實後才補更具體的說法。

## Considered Options

- **只要送出者同意**：實作最簡單，但行程內容（owner 的資料）在 owner 不知情下被交給 AI。
- **只要 owner 同意**：owner 的資料有保護，但旅伴的訊息與名稱在旅伴不知情下被送出。
- **把舊的操作授權回填成已同意**：使用者零摩擦，但等於宣稱他們看過新文案。
- **同意判定放在各個 client**：Flutter 與 web 各寫一份，必有繞過的 caller。

## Consequences

- 要同時改 **新 api 與舊入口**：目前網站與 agent 呼叫的是舊入口，只有新 api 有閘門會被繞過；同意資料在共用的 D1，兩邊讀同一份。
- 上線順序：api（旗標關）→ web／Flutter 的同意畫面 → 開旗標；否則 App 會在不知情下無法使用 AI。
- 資料表要新增（migration 只加不刪）；稽核只存同意事實，不存行程內容。
- **執法點有兩個**（2026-11-03 補）：除了三個受管制入口（建立請求時），agent 取得 owner 權限 token 的 `mint-restricted` 再檢查一次——owner 一定檢查；送出者若對應到使用者也檢查。
  這涵蓋「旗標啟用前已排隊」與「撤回和建立請求同時發生」的請求，也是**服務 token 建立的請求**唯一的執法點（入口閘門對服務 token 豁免；送出者不是使用者的請求只看 owner）。
  已簽發的 token（2 小時）與已開始的工作不撤銷，沿用 ADR-0007「不保證能停」，文案照實寫。

**未決**（不影響模型）：責任人與聯絡信箱（owner 提供）；Claude 帳號「改善模型」設定的核實結果；處理方條款連結。
